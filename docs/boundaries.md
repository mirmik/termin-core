# Пограничная служба

У Core есть простой тест на гражданство: может ли сущность существовать без
графики, сцены, физики, редактора и конкретного приложения?

Если ответ требует долгого монолога, заявка уже выглядит подозрительно.

## Что здесь уместно

Хороший кандидат в Core:

- нужен нескольким доменным библиотекам;
- выражается через нейтральные данные или language boundary;
- тестируется без engine lifecycle;
- не требует GPU, window system, scene graph или asset database;
- имеет смысл как часть установленного SDK;
- не тащит за собой половину верхнего этажа.

Именно поэтому здесь есть `Vec3`, dispatcher и inspect contract. Они ничего не
знают о том, кто ими пользуется.

## Что остаётся снаружи

Core не принимает зависимости на:

- graphics, images, meshes и shaders;
- assets и scenes;
- physics;
- editor и player;
- engine/application packages.

Запрет относится не только к линковке. Нейтральный модуль, внутри которого
спрятаны понятия `active_scene`, `selected_entity` или `render_device`, уже
перешёл границу, даже если заголовок назван достаточно абстрактно.

MCP server, например, может исполнить запрос через переданный host context.
Но сам Core не объявляет, что в context обязательно должна быть сцена. Orbit
camera может считать pose, но не знает, какой renderer применит матрицу. Log
queue принимает записи, но не знает, какая editor console их покажет.

## Граница — это установленный SDK

Внешние потребители используют только результат установки. Никаких
`../termin-core`, `add_subdirectory()` чужого checkout или «временно найдём
header в source tree».

Это ограничение делает архитектуру физической. Без него диаграмма зависимостей
остаётся добрым намерением, которое первая срочная сборка перепишет маркером на
стене.

## Вопросы перед переносом кода

Перед тем как опустить utility в Core, полезно спросить:

1. Какие два независимых нижних потребителя уже нуждаются в нём?
2. Как выглядит его C/C++ или Python contract без терминов верхнего домена?
3. Кто владеет памятью, callbacks и shutdown?
4. Может ли installed consumer проверить его без исходников Termin?
5. Не превращаем ли мы Core в склад «общего», который просто некуда положить?

Если ответы ясны — добро пожаловать вниз. Если нет, код почти наверняка лучше
понимает собственный домен, чем мы сейчас готовы признать.

Формальное описание границы находится в
[архитектурном решении](architecture/2026-08-13-core-domain-repositories.md).
